Are Your AI Agents Actually Better, or Just Using More Compute?

How to check whether a multi-agent LLM system beats a single model that is given the same token budget.

A debate between five agents over three rounds makes fifteen model calls, and in every round after the first each agent also reads what its peers wrote. Many evaluations compare that system against one greedy call from a single model. When the multi-agent system wins, three things are tangled together: communication between agents, the extra independent samples, and the extra test-time compute.

The fix is to compare against a single model that gets to spend the same tokens, for example by sampling several answers and taking a majority vote (self-consistency). I wrote PACE to make that comparison routine.

What changes with a fair baseline

In PACE: More Agents, More Samples, or More Thinking? (arXiv:2611.17610), I audited 516 unique multi-agent configurations from 9 published empirical studies and grouped each comparison by the single-agent baseline it used: one greedy pass (Category A), several sampled answers (Category B), or a budget-matched baseline (Category C).

  • Most apparent wins disappear. In 318 paired contrasts where a study reported both a greedy baseline and a sampled one, most multi-agent wins over the greedy pass became zero or negative against the sampled baseline.
  • The average difference is negative. Across 474 Category B and C contrasts, the mean accuracy difference between the multi-agent system and the baseline was −4.2 percentage points. This is a descriptive mean over heterogeneous studies, not one controlled experiment.
  • A controlled test agrees. In a controlled experiment on MMLU-Pro (llama3.1:8b, 250 items), neither multi-agent debate (−1.5 points) nor mixture-of-agents (−7.2 points) exceeded the self-consistency frontier at equal tokens.
Mean difference between multi-agent systems and sampled or budget-matched single-agent baselines (474 contrasts, 8 studies). Descriptive mean; see Section 6.1 of the paper for the meta-analytic model.

Five agents are not five samples

Debate costs more than its call count suggests, because prompts grow with peer messages. Suppose each call has 400 prompt tokens and 100 completion tokens, and in each round after the first, every agent reads the previous round's messages from its peers. Then a 3-agent, 2-round debate makes 6 calls but uses 3,600 tokens, the cost of 7.2 independent samples. The paper gives the general formula:

$$k_{\mathrm{tok}} = KT + (T-1)\,K(K-1)\,r, \qquad r = \frac{\ell}{c_p + \ell}$$

where $K$ is the number of agents, $T$ the number of rounds, $c_p$ the prompt tokens and $\ell$ the completion tokens per call. If agents re-read the full history, the cost grows quadratically in $T$.

For 4 agents, the token-equated sample count pulls away from the call count as rounds increase (r = 0.20, illustrative inputs).

Which way to round. Here $k_{\mathrm{tok}} = 7.2$, so no whole number of samples matches exactly. An 8-sample vote spends at least as many tokens as the debate: if the debate beats it, that is a real gain. A 7-sample vote spends fewer: if it matches or beats the debate, communication did not pay for its tokens. Neither pool is "the same budget"; each is fair in one direction.

When communication can help

PACE does not say multi-agent systems never work. With a single shared prompt, exchanging messages adds no information that independent samples lack. That leaves three candidate settings where communication can beat equal-compute sampling:

  1. Split evidence. Agents hold different pieces of information that no single agent sees. In a hidden-profile positive control (200 items), split-view debate beat split-view voting by 7.3 points. It still scored below a placebo debate and below four-option chance, which is why placebo controls matter.
  2. An external verifier. A unit-test runner or formal checker filters proposed answers more cheaply than regenerating them, provided the single-agent baseline gets the same verifier.
  3. Models that make different errors. Combining different model families can lower the correlation between errors and raise the effective number of independent votes.

These are candidates, not effects the audit established.

  • From the command line: the open-source toolkit is on GitHub.
pip install git+https://github.com/mahmoudsajjadi/pace.git
pace pool-size --agents 3 --rounds 2 --prompt-tokens 400 --msg-tokens 100
# k_tok 7.200 (r=0.2000), recommended pool size 8

Checklist before you ship or review a multi-agent system

  1. Log the resources of both arms: thinking tokens, total tokens, dollar cost, latency, number of independent samples, and external tool or verifier calls.
  2. Compare against the sampling frontier first: self-consistency with $k \ge k_{\mathrm{tok}}$ samples, and report the gap with an interval.
  3. Give both arms the same tools: never give the multi-agent system a code executor or test runner that the baseline lacks.
  4. Run a placebo for communication claims: replace peer messages with length-matched text from another item. If accuracy stays the same, the gain came from extra context or compute, not from coordination.
