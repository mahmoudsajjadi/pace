## 2. Strategic positioning

**Do not** position as the first multi-agent benchmark, leaderboard, or cost-accounting paper. Those exist (HAL, TeamBench, AgentWorld, MASBench, MAC-Bench, MASEval, MAESTRO; verify each). **Defensible narrow gap to test:** a reusable, resource-matched attribution standard for the incremental value of inter-agent communication over the strongest non-communicating baseline, across models, task structures and declared budgets, with validated software and real per-instance data.

Canonical principle (appear in abstract, intro, discussion, checklist):
"A reported advantage of multi-agent systems should not be attributed to coordination unless it survives comparison against the strongest non-communicating baseline under explicitly declared resource constraints."

Evidence balance: report positive and negative matched-budget results (Wunderlich, ColMAD positive; Tran and Kiela, Ferreira, Nguyen, Bertalanic, Ann, Zhu negative). Make task structure and architecture central; the 45% threshold is secondary and study-specific.

Three research questions: RQ1 does communication add value over the strongest non-communicating alternative at a declared budget; RQ2 when (task decomposability, sequential dependency, context fragmentation, model capability, diversity, agents/rounds); RQ3 how should multi-agent systems be evaluated and reported.

## 3. Formal framework to implement (math)

- Resource vector R = (thinking tokens, total tokens, cost, latency, sample count, tool scaffolding). Not totally ordered, so never use an unconstrained f(R).
- Constrained frontier: f(B; t, m) = sup over single-agent policies pi with E[R(pi)] <= B of E[accuracy(pi; t, m)]. It is generally unobserved; distinguish theoretical frontier, best measured baseline, and the baseline extracted from a source paper.
- Pairwise coordination delta (preferred, avoids winner's curse): Delta_comm(pi_comm, pi_indep; B, t, m) = E[acc(pi_comm)] - E[acc(pi_indep)] with both satisfying B, and the matched resource named.
- "Coordination Premium" Gamma(B, t, m) = best communicating minus best non-communicating at budget B: use only as a plain-language label after a prior-art check (nearby "tax" metaphors exist: interaction tax, coordination tax, swarm tax). Max over architectures is biased upward; require equal, preregistered tuning effort.
- Sampling gap identity: Delta_gap = (p_MAS - p_sampled) - (p_MAS - p_single) = p_single - p_sampled. p_MAS cancels, so it measures baseline strengthening, not a coordination effect. State this prominently. The decomposition is an accounting identity, not causal identification.
- Four baseline categories: A greedy single pass; B sample-matched (same k, tokens/cost unconstrained); C resource-matched (thinking tokens, iterations or cost, named); D Pareto/frontier sweep. Never call Category B "compute-matched".
- Three-layer spec: (1) consumed resources (input/output/reasoning/cached/communication tokens, API cost, latency p50/p95, energy/GPU time when measurable); (2) architecture and execution (agents, calls, parallel vs sequential, rounds, tools, retries, context use and truncation); (3) experimental context (model revision/digest, dataset split, prompts, decoding, seeds, tools, contamination controls, actual n evaluated). Evidence statuses: strictly controlled, approximately controlled (with measured deviation), measured but unmatched, unreported, not applicable.
- Resource regimes reported separately, never merged: equal samples, equal generated tokens, equal total tokens, equal cost, equal latency, Pareto.
- Separate final aggregation (voting) from iterative communication. Include a communication-off ablation and a placebo-message control (borrow Bertalanic and Fortuna's noise control and cite them).
- Section 3.1: engage Tran and Kiela's stated conditions (fixed reasoning budget, perfect context use, single agent degrades with context or more compute) or remove the DPI claim.

## 6. Controlled experiment (the biggest upgrade)

Design (preregister on OSF before confirmatory runs; do not make success depend on debate losing):
- Architectures per model checkpoint: single greedy CoT; self-consistency / best-of-N; independent agents with final vote (no communication); single-agent self-refinement at matched tokens; multi-agent debate; communication-off ablation; placebo messages (irrelevant or content-free, matched length); optionally planner-worker or critic-verifier. Expert-designed systems kept separate from auto-generated ones.
- Primary comparison, fixed in advance: debate vs independent sampling/self-consistency at declared matched budgets, within the same checkpoint. Cross-model teams are not evidence of communication benefit without their own controls.
- Models (verify current IDs, digests, licenses, context, availability first; check what Ollama already has): Qwen3.5-9B, Gemma 4 12B, Ministral 3 8B, Llama 3.1 8B Instruct, DeepSeek-R1-Distill-Qwen-7B (derived from Qwen2.5, so not an independent family), optionally one hosted frontier model if budget allows. Apache 2.0 / MIT are permissive; Llama is "open-weight", not OSI open source. 4-bit quantization, fixed 8K context at first, monitor actual VRAM/offload on the RTX 4070 12GB; record Ollama version, quantization, digest; do not let transcripts silently exceed context (log truncation). Optional quantization sensitivity on a subset.
- Task tracks: independent reasoning (negative control), complementary information, sequential dependencies, long-horizon tool execution; classify by structure (parallel decomposability, sequential depth, information complementarity, partial observability, context fragmentation, tool concurrency, verification availability) after checking prior art for each. Candidate sources: GSM8K, HotpotQA/MuSiQue, MMLU-Pro/BBH, HumanEval, plus adapters to TeamBench/MASBench/AgentWorld/MAC-Bench only if licenses permit.
- Budgets: low/medium/high/very high; each regime reported separately.
- Size: power analysis first (reviewer rule of thumb: roughly 100-200 items per task, at least 3 repeated runs, then pre-register final n after a pilot). Keep per-question binary outcomes for every item and condition to measure real phi.
- Outcomes: primary accuracy, cost, latency; secondary calibration, reasoning alignment, reliability across runs, error correction vs harmful answer changes, conformity, answer-change rate; cost and tokens per successful task. Do not infer hidden reasoning tokens a provider does not expose; label unavailable.
- Statistics: paired analysis at item level (McNemar, cluster-aware bootstrap), hierarchical logistic model (task, instance, model random effects) as secondary, cluster-robust SEs, Benjamini-Hochberg across confirmatory hypotheses, confirmatory vs exploratory split, sensitivity (alternate metrics, outliers).
- Replace `code/run_calibration_anchor.py` synthetic role with a live runner; keep synthetic as clearly labelled smoke test.

## 12. Final quality bar

A researcher should be able to answer with this system: Is a new model better alone? Does it gain from independent sampling? From communication? At the same token, cost and latency budgets? On which task structures? Are gains reliable and reproducible? What does coordination cost? Scientific validity, measured results, independent verification and genuine usefulness outrank branding.
